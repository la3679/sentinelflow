## Read latency

Thirty requests per endpoint, paced a quarter of a second apart. **The pacing is deliberate**: the standard rate allowance is 300 a minute with a burst of 60 (ADR-0017 §2), and a tight loop would spend the burst and start timing the limiter's refusals rather than the query behind them. Pacing does not change a latency distribution.

## Ingestion

One burst, because the burst is what the limiter permits at once. **The sustained ceiling is a configured policy** — 600 a minute (ADR-0017 §2) — rather than a property of the pipeline, so measuring through it would measure the policy. This benchmark does not raise the limit to flatter itself; it stays under the burst and says what one accepted transaction costs.

**Accepted per second is not a throughput ceiling.** It is what this burst achieved at this concurrency on this machine while the rest of the stack was running beside it.

## End to end: accepted to assessed

Measured from the database rather than from an endpoint, because the question is when the pipeline finished rather than when a reader could see it. Kafka, the outbox relay's poll interval, the consumer and the scoring call are all inside this one number — the system emits no per-hop timing, so breaking it down would mean inventing the split.

| Field                           | Value |
| ------------------------------- | ----- |
| Transactions                    | 100   |
| Seconds until all were assessed | 5.0   |
| scored, HIGH, alert raised      | 100   |

**The outbox relay polls every 500 ms by default** (ADR-0005), so roughly half of that is in every one of these figures before anything else happens. Nothing in this pipeline is real-time and the design says so.

## What this benchmark does not measure

- **Sustained throughput.** The rate limiter's ceiling is the binding constraint by design, and this run stays under it rather than raising it.
- **Anything under contention from a second client.** One driver, one machine, the stack running beside it.
- **Cold starts.** The stack was already warm; a first request after a restart pays for connection setup and JIT that nothing here isolates.
- **The console.** These are API measurements. What a browser renders adds a network hop, a bundle and a render this does not touch.
- **Any hardware but the one named above.** Run it yourself; the command is `make bench`.
